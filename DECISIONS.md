# Decisions, validation and remaining limitations

## What was checked

- The earlier M1 checks used real MiniLM embeddings, Chroma and Tesseract: two-column ordering, scanned-PDF OCR and the four-mode retrieval evaluation. The earlier M2 acceptance checks used scripted LLM providers, including a live HTTP stop test under one second; a real Ollama model has **not** been exercised in this environment.
- The requested preliminary fixes were exercised: a generated PDF with a title, two authors, abstract, DOI and arXiv ID was parsed; fallback and identifier punctuation were tested. With a deliberately empty Hugging Face cache, the suite ran with clear skip messages for all seven real-embedding tests. Metadata parsing remains heuristic rather than a guarantee of correctly interpreting every paper layout.
- M3: the Section 18.4 test created ten chats on three topics, used **real** locally cached MiniLM vectors and Chroma, and verified at least 8/10 nearest neighbours share the topic at the default threshold, plus a repeated-question duplicate. Dismissal, title/summary jobs, clustering, export and labels were tested. The LLM title/summary/topic responses in tests were **mocked**; no real Ollama quality claim is made.
- M4: a real uploaded PDF was retrieved and streamed through a mock LLM. Every returned PDF citation had a page and boxes that intersected extracted word rectangles; the debug renderer produced a PNG with the boxes, and the file endpoint returned `206` with the exact requested byte range. This is a synthetic fixture, not a representative benchmark of every PDF/OCR layout.
- M5: offline intelligence returned `online:false` without a network request; resources and evidence scoring were tested with mocked provider responses. A live opt-in known-DOI check for `10.1038/nature12373` returned the full response and all four evidence parts using real Semantic Scholar, OpenAlex and Crossref responses. That public API check is rate-limit and network dependent; earlier attempts encountered Semantic Scholar 429 responses. GitHub, YouTube and learning-concept generation were tested with mocks or documentation, not authenticated production credentials.
- M6: note creation, updates, deletion, FTS5 body/tag search, Markdown export, PDF anchors, reference validation, old-database FTS rebuild and opt-in note retrieval were tested. The opt-in retrieval test used real locally cached MiniLM/Chroma. Run `pytest -q`; tests needing unavailable embedding weights skip with an explanatory message.

## Official external API verification (2026-10-30)

- Semantic Scholar: official [Academic Graph API schema](https://api.semanticscholar.org/api-docs/graph) documents paper IDs, `externalIds`, `title`, `year`, `venue`, `publicationDate`, `citationCount`, `influentialCitationCount`, `authors`, `openAccessPdf`, `publicationTypes`, search and the `x-api-key` header. The known DOI was tested live.
- OpenAlex: official [work attributes](https://help.openalex.org/data/works/attributes/) and [works overview](https://developers.openalex.org/api-reference/works) document `title`, `publication_date`, `type`, `primary_location`, `cited_by_count`, `counts_by_year`/`cited_by_count`, `is_retracted` and DOI lookup. Live unauthenticated access worked here. OpenAlex's [deprecations page](https://developers.openalex.org/guides/deprecations) says the old mailto polite pool was replaced with API keys, while its quickstart still describes some basic unauthenticated access. `OPENALEX_API_KEY` is therefore configurable; do not rely on unauthenticated availability.
- Crossref: [retraction documentation](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/), [filters](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/) and its [production API update notice](https://community.crossref.org/t/deprecating-retraction-watch-annotations-in-the-labs-api/15884) document `message`, `update-to`, `updated-by`, `DOI`, `type`, `updates` and `update-type`. Crossref `relation` is documented as a general relation field, but arbitrary relation types and correction notices are **not interpreted** as retractions; the contract has no separate correction output.
- GitHub: [Get a repository](https://docs.github.com/en/rest/repos/repos#get-a-repository) documents `stargazers_count` and `pushed_at`; public repository authentication is optional. No live authenticated GitHub test was run.
- Hugging Face: official [`paper_info`](https://huggingface.co/docs/huggingface_hub/package_reference/hf_api) documents an arXiv paper lookup and 404 semantics; the official `huggingface_hub` source for `HfApi.paper_info` uses `/api/papers/{id}`. This measures **presence of a paper page**, not whether a paper is in the daily trending list. The exact raw HTTP endpoint was verified in official SDK source and live HTTP, but is not separately documented as a stable public REST contract.
- YouTube: official [search.list](https://developers.google.com/youtube/v3/docs/search/list) and [search resource](https://developers.google.com/youtube/v3/docs/search) document `part`, `type`, `maxResults`, `q`, `items`, `id.videoId` and `snippet.title`. A YouTube API key was not available for a live test; without one, generated links are search links.

## Assumptions and limitations

- Online features are off by default; only `app/core/intelligence/online.py` makes external feature requests, with a host allowlist, retries, timeouts and an on-disk cache. Local LLM calls to Ollama are separate. Provision embedding/reranking weights separately; runtime model loading is local-cache-only. The health connectivity check runs only when online lookups are enabled.
- `citations.last_12_months` is an approximation: the current and previous calendar-year OpenAlex counts are summed. The calculation is disclosed in the evidence note and is **not** a rolling 12-month count. Missing provider fields remain null and are never fabricated. Peer-review evidence uses the publication type as a proxy; a non-retracted status is not a guarantee of quality.
- Offline intelligence includes `doi` and `arxiv_id` as extra fields because Section 11.3 requires these local fields although the Section 12.6 example omits them. It reports a local date only when explicitly labelled with an ISO date in extracted text. The model-selected learning concept fallback is the local document title if extraction fails; links are built from verified APIs or fixed templates, never from LLM output.
- Title extraction uses largest first-page font lines, authors between title and abstract, and abstract through the next recognized heading. Affiliations are heuristically excluded; complex layouts, citations or OCR errors may still require manual identification. A metadata chunk without traceable page-one boxes is excluded from PDF retrieval rather than emitting a bogus highlight. Existing PDF metadata rows are backfilled from page-one boxes when possible.
- Notes are embedded in a separate opt-in collection; only notes attached to selected documents participate in retrieval. Unattached notes remain searchable with FTS5 but are not added to RAG. Note chunks are labelled `Your note`; the setting remains off by default. Their indexing is asynchronous.
- For the first message a chat title falls back to the first 40 characters. Background title/summary and topic labels use the local model; on invalid/unavailable topic output a conservative title-based or `Related chats` label is used. Embedding and question indexing are asynchronous; related-chat and duplicate results may lag until jobs finish.
- The initial citation SSE event has `cited:false` until generation completes; persisted citations are updated afterward. Invalid marker numbers are flagged in debug rather than stripped. Deleted citations retain snapshots, with null `chunk_id`/boxes; old `doc_id` is reconstructed from the debug record. Previously deleted legacy citations cannot be recovered.
- Hybrid min-max normalization assigns missing candidates zero after scaling. Oversized table rows are never split; repeated headers are excluded from source character offsets. `notes_in_retrieval` defaults false, and settings weights are constrained to sum to one.
- Other LLM providers and automatic online ingestion enrichment are not implemented. Prompt grounding is not a formal guarantee that a model response is factually supported.


## M7–M9 decisions and evidence

- **M7:** The planted two-paper conflict test uses a **scripted local-LLM response**, not a real LLM; it checks normalization, graph passage provenance, conflict filtering and cleanup after deletion. Invalid JSON is retried once then skipped with a warning. Entities and edge types are validated, provenance points to matching excerpts, and Paper edges are created only for explicit structured relations; an entity mention alone does not imply a relation. Claims require literal numeric values and named dataset/metric in the source excerpt. These conservative checks cannot prove a model-extracted relation is correct.
- Optional `cites` edges use Semantic Scholar references only between uploaded documents with matching DOI and an actual source excerpt mentioning the target DOI or title. Previously fetched reference IDs permit resolution if the target is uploaded later. A cited paper lacking a DOI, a matching uploaded target or a traceable excerpt is omitted, even if Semantic Scholar knows the link. References are paginated; network errors produce no fabricated edges. Reference behavior was tested with a **mock** response, not against the live service. The official [Semantic Scholar Swagger](https://api.semanticscholar.org/graph/v1/swagger.json) was inspected: `GET /paper/{paper_id}/references`, `data[].citedPaper.externalIds`, `fields`, `limit` (up to 1000), `offset`, and optional `next` are documented. No source text is sent.
- **M8:** The real cached `cross-encoder/nli-deberta-v3-small` was loaded local-only on CPU and checked on one supported and one contradictory pair; this is an operational check, not an accuracy benchmark. Its official [model card](https://huggingface.co/cross-encoder/nli-deberta-v3-small) and config identify labels `contradiction`, `entailment`, `neutral`; probabilities are softmaxed and the maximum entailment across excerpts is used. If NLI is missing, the local LLM fallback is tested with a **mock judge**; if both fail, the job fails and `faithfulness` stays null rather than inventing a label. SSE and GET field behavior were tested with a mock NLI function. The stream waits up to three seconds after `done` for the optional event; the job continues after that.
- Similarity uses 8-gram exact matches and local sentence embeddings for paraphrases. Tests exercise exact and quote exclusion, document exclusion, API jobs and **mocked embeddings** for the paraphrase branch. `overall_percent` is based on target word counts, not sentence count. For corpus mode, target offsets refer to reconstructed extracted text with overlapping chunks stitched; PDF extraction and chunk boundaries can make it differ from original file byte offsets. Quote detection is heuristic. `web` is intentionally disabled regardless of `confirm_send`; nothing is sent externally.
- **M9:** The 501-page synthetic PDF test checks batch sizes at most 64, progress and SQLite/Chroma ID agreement using **mocked vectors**, not real embeddings or a measured process-RSS limit. PDF pages stream through the reader, with a sample of at most 100 pages for repeating margins; one exceptionally large page may still consume substantial memory. Office and text readers are not claimed to have this large-PDF memory bound. SQLite staging and persistent Chroma backup plus a durable recovery journal restore pre-ingest vectors after injected commit failure and simulated interruption. A separate test verifies shutdown waits for the cooperatively cancelled ingestion thread. This does not prove behavior under every possible filesystem, power-loss or Chroma corruption scenario. Single-process ownership of a data directory is assumed.
- `scripts/run_evaluation.py --answers --models ...` implements Section 18.6 over the fixture questions and ten unanswerable questions, with missing judgments/errors counted and excluded from faithfulness. SSE parser and evaluation arithmetic were tested with **scripted HTTP/client responses** only. Reported token rate uses the backend's streamed token-event count, not an independent tokenizer.
- `scripts/smoke_real.py` uses real HTTP only, with no mocks; it requires a running PaperWise API, Ollama and provisioned weights. **It has not been run against a real Ollama model here**, because Ollama was not available. Neither real answer quality nor a real Mac smoke pass is claimed. `--help` and the helper's mocked transport were checked.
- Normal model operation is local-cache-only. With an empty Hugging Face cache, real-embedding and real-NLI tests explicitly skip; fallback paths are tested separately. The generated OpenAPI includes the Section 12 graph/similarity fields, message faithfulness schema and SSE media type. Runtime data and model weights are excluded from the source archive.

### Final test runs

- `OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 pytest -q -rs`: **65 passed**, with three nonfatal dependency/deprecation warnings. This includes the real local NLI pair check, real cached MiniLM checks, and the mocked tests identified above.
- With a new empty `HF_HOME`, `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1`: **57 passed, 8 skipped**, one warning. Seven embedding-dependent tests and the one NLI-weight test reported explicit cache-missing reasons.
- No unmocked Ollama smoke test or answer-quality benchmark was run. Results from running those scripts on another machine will depend on its models and installation.
